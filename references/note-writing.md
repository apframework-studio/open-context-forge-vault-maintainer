# 知识笔记编译规则

这份规则沿用原 Skill 的“分析卡 → 编译计划 → 长期笔记”方法，但不假定 vault 使用 `20-wiki/` 等固定目录。先读目标 vault 的用途和现有笔记惯例，再决定写入形式。

## 从来源到判断

- 分析卡保存原文指纹、`E1` 等证据 ID、精确行区间及简短摘录或独立可理解的发现。不要把整篇原文复制到分析卡。
- 编译计划列出创建、更新和跳过的候选笔记；每个新增笔记说明为什么现有笔记不能承载。已有同义笔记优先局部更新，冲突观点明确并列和标注来源。
- 后续写回默认复用分析卡中的证据。证据不足或相互矛盾时，只补读所需行区间并更新分析卡；原文指纹改变则重新分析。
- 只有 `compile_now` 且证据足够时写长期笔记。`defer`、`keep_raw_only` 和 `ask_user` 保留原文及过程文件，不制造确定结论。

## 按内容选择笔记

| 类型 | 何时创建 | 最少包含 |
| --- | --- | --- |
| 来源摘要 | 原文值得日后按来源回看 | 核心主张、适用场景、可复用点、原文快照、实际派生笔记 |
| Concept | 有稳定、可复用的概念 | 定义、为何有用、边界、相关已有笔记及来源 |
| Claim | 有值得复用的判断 | 清楚的判断句、逐项证据、反例或反方观点、适用条件 |
| Framework | 有可复用的步骤、结构或模型 | 目的、结构、使用方式、适用范围和限制 |

这些是可选的内容形态，不是每篇文章都要产出四类笔记，也没有固定数量。对标准 vault 可使用 `assets/templates/` 下的对应模板；接入已有 vault 时遵循其目录、frontmatter 和链接习惯。

## 可追溯性

- 标准 vault 的每个编译笔记包含 `type`、`source_snapshot` 和 `source_fingerprint`，正文至少给出一个 `path/to/source.md#L12-L18` 形式的证据位置。引用的路径以 vault 根目录为基准。
- 在紧邻结论的位置说明：这是作者的陈述、基于原文的推断，还是独立核对过的事实。说明证据支持到哪里，以及不适用或尚未验证的部分。
- 来源摘要列出确实存在的派生笔记；Concept 连到相关概念，Claim 写反例或边界，Framework 写适用范围与限制。不要为凑链接指向不存在的笔记。
- 不复制完整原文，不改写原文快照。编辑已有笔记只改相关段落，保留用户的其他内容。

## 写回后

标准 vault 更新 `wiki/index.md` 并追加 `wiki/log.md`；接入已有 vault 只更新它实际使用的索引或日志。对本次新增或修改的笔记运行 `check-notes.js`，并运行 `check-vault.js` 检查原文快照。自动校验只能发现可机械判定的问题；Agent 仍需检查证据是否真正支持结论，以及同义笔记是否被重复创建。
